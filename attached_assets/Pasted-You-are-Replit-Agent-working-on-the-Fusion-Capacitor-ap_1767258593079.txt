You are Replit Agent working on the Fusion Capacitor app + backend (Replit monorepo). Goal: implement OPTION 1 “Tap to answer” call notifications for Agora RTC (NOT CallKit/VoIP). Calls/media stay direct via Agora; backend only coordinates call invite + push notification + token generation.

CONTEXT
- We already have iOS APNs working via Sendbird + Capacitor. iOS device tokens are being captured and registered to Sendbird.
- We use Agora RTC for video/audio. Backend already generates RTC tokens via agora-token package at /api/agora/token.
- We need cross-platform call invites:
  - iOS: send a normal APNs push (production) to the callee
  - Android: send a normal FCM push to the callee
- When user taps push, the app navigates to an “Incoming Call” screen, then on Accept it joins Agora channel.

REQUIREMENTS (do ALL)
1) DATABASE / STORAGE
- Add a table/collection for device push tokens if not present.
- Must store per user:
  - userId (our app user)
  - platform: 'ios' | 'android'
  - token (string)
  - provider: 'apns' | 'fcm'
  - environment: 'production' | 'sandbox' (store if you can detect; default 'production' for TestFlight)
  - updatedAt timestamp
- Ensure a user can have multiple devices (multiple rows), but avoid duplicates per token.

2) PUSH TOKEN REGISTRATION ENDPOINTS
- Implement/confirm POST /api/push/register that accepts:
  {
    "platform": "ios"|"android",
    "provider": "apns"|"fcm",
    "token": "<token string>",
    "environment": "production"|"sandbox" (optional)
  }
- Auth required; map to current logged-in user.
- Upsert token row (if token exists update userId/updatedAt; else insert).
- For iOS (provider apns): ALSO register token with Sendbird for that Sendbird userId.
  - Our Sendbird userId should match the app user id we use for chat.
  - Ensure we don’t leave old tokens causing BadDeviceToken. Do one of:
    A) Before registering new iOS token: remove all previous iOS tokens for that Sendbird user OR
    B) If removal is too hard, at least remove tokens that don’t match current environment (sandbox vs production) and de-duplicate.
  - Log clearly: “Registered iOS token with Sendbird”.

3) CALL INVITE ENDPOINT (core)
- Implement POST /api/call/invite (auth required).
Request:
  {
    "calleeUserId": "<user id>",
    "callType": "video"|"audio"
  }

Backend logic:
- Create callId (uuid or nanoid).
- Create channelName: "fusion_" + callId
- Store call session in DB with:
  - callId, channelName, callerUserId, calleeUserId, callType, status ('ringing'|'accepted'|'declined'|'missed'), createdAt
- Do NOT generate RTC token here if using Option B below (preferred).
- Send a push notification to ALL callee devices:
  - For iOS devices -> send via Sendbird push to that user OR via direct APNs if already implemented; prefer Sendbird since APNs is working there.
  - For Android devices -> send via FCM from backend (requires Firebase service account/legacy key in env). If FCM isn’t set up, implement it and read credentials from env vars.

Push payload MUST include data:
  {
    "type": "rtc_call_invite",
    "callId": "<callId>",
    "channel": "<channelName>",
    "callerId": "<callerUserId>",
    "callerName": "<caller display name if available>",
    "callType": "video"|"audio"
  }
Notification text:
- Title: "Incoming call"
- Body: "<callerName> is calling you" (fallback to “Someone is calling you”)

Response to caller:
  {
    "callId": "...",
    "channel": "...",
    "callType": "...",
    "calleeUserId": "..."
  }
